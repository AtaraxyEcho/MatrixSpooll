## 2. 交付范围

### 2.1 软件交付物

正式交付应包含与交付版本完全对应的以下内容：

- MatrixSpooll 完整源代码，包括 `frontend/`、`server/`、`lib/`、`scripts/`、数据库迁移和构建配置。
- `LICENSE`：GNU AGPL-3.0 完整许可证文本。
- `NOTICE`：ArcReel 来源、版权、修改版本和界面署名要求。
- `README.md`、`README.en.md` 和 `website/docs/` 中与当前版本相符的使用及部署说明。
- `Dockerfile`、`deploy/` 和 `deploy/production/` 中的本地构建及部署配置。
- `pyproject.toml`、`uv.lock`、前端依赖清单和其他可重现构建所需文件。
- 本次定制版本的变更记录、验收记录和已知限制。

交付源码应能在不依赖交付方私有路径的情况下完成安装、构建和启动。API Key、数据库密码、认证密钥、客户文件和生产环境 `.env` 不应写入源码包。

### 2.2 部署交付物

根据合同约定，交付以下部署材料：

- `deploy/.env.example`：SQLite 单机部署模板。
- `deploy/production/.env.example`：PostgreSQL 生产部署模板。
- Docker 本地构建配置。应用镜像使用本地 `docker compose build` 构建，不依赖 MatrixSpooll 的公共 GHCR 镜像仓库。
- 健康检查、日志查看、升级、备份和恢复操作说明。
- 第三方模型供应商配置说明，以及需要客户自行申请的 API 凭据清单。

当前数据库和内部协议中的 `arcreel` 标识（例如 `.arcreel.db`、`ARCREEL_*` 和 PostgreSQL 默认数据库名）属于兼容性标识，交付时不应自行重命名。若客户要求更换这些标识，必须单独制定数据迁移、回滚和兼容性验证方案。

### 2.3 定制功能范围

本交付版本以实际验收清单为准。当前定制范围包括：

- MatrixSpooll 品牌、图标和界面来源声明。
- 自由创作项目模式，以及首页创作输入框。
- Agent、图片生成、视频生成等输入框模式控制。
- 模型能力联动和生成参数控制。
- 自由创作项目详情页及无限画布交互。
- 参考素材、首尾帧和文本资源相关交互。
- 视频生成失败信息解析与用户可读提示。
- 项目列表、设置页、关于页和部署文档的界面调整。

未列入验收清单的第三方模型能力、供应商策略、模型稳定性和生成内容质量不属于本项目的确定性承诺。

### 3.1 软件许可证

MatrixSpooll 是 ArcReel 的修改版本，整体按 GNU AGPL-3.0 发布。交付方可以收取定制开发、部署、培训、维护和技术支持费用，但这不等同于将 AGPL 软件转化为闭源专有软件。

交付包必须保留：

- `LICENSE` 完整文本；
- `NOTICE` 完整文本；
- ArcReel 原始版权和来源链接；
- MatrixSpooll 的修改声明和修改日期；

### 3.2 源码交付方式

本项目不要求将定制版本公开发布到公共 GitHub 仓库。可以采用以下任一方式向客户交付对应源码：

- 客户专属的私有 Git 仓库；
- 加密压缩包或客户内部文件服务器；
- 客户服务器上的源码目录；
- 其他能够让客户取得、保存和修改完整对应源码的方式。

如果客户只接收 Docker 镜像、编译版本或其他非源码形式，必须同时提供该版本的完整对应源码，或者提供符合 AGPL-3.0 第 6 节的有效源码获取方式。采用许可证规定的源码获取方式时，不得设置超出许可证允许范围的费用、密码或其他复制障碍，也不得附加禁止修改或再分发 AGPL 代码的条款；定制开发和技术支持服务仍可按合同收费。

### 3.3 在线服务场景

如果客户或交付方运行 MatrixSpooll，并允许用户通过网络远程使用修改后的程序，则应向所有实际远程使用该服务的用户提供对应源码获取入口。该入口可以位于登录后的客户门户或应用的法律/关于页面，不要求使用公共 GitHub 仓库，但不能只向签约联系人提供而让其他实际用户无法获取。

如果系统只部署在客户内部网络，并且没有向客户以外的公众提供服务，源码可以通过客户内部交付渠道提供，但仍应确保所有实际远程使用该服务的用户都能取得对应源码。最终交付方式仍应以合同、部署范围和法律顾问意见为准。

客户获得源码后，可以依据 AGPL-3.0 使用、修改和再分发。交付合同可以约定定制服务、维护响应时间、保密信息、客户数据和商业支持范围，但不应禁止客户行使 AGPL 赋予的源码使用和再分发权利。

## 4. 部署说明

### 4.1 SQLite 单机部署

在项目根目录执行：

```bash
cd deploy
cp .env.example .env
```

编辑 `.env`，至少设置：

```dotenv
AUTH_USERNAME=admin
AUTH_PASSWORD=请设置强密码
AUTH_TOKEN_SECRET=请设置长期固定的随机密钥
```

使用本地构建启动：

```bash
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=100 arcreel
curl -f http://localhost:1241/health
```

默认持久化内容位于 `deploy/projects/`、`deploy/logs/` 和其他 Compose 挂载目录。数据库与项目媒体需要同时备份。

### 4.2 PostgreSQL 生产部署

在项目根目录执行：

```bash
cd deploy/production
cp .env.example .env
```

设置认证参数和 `POSTGRES_PASSWORD` 后，使用本地构建启动：

```bash
docker compose build arcreel
docker compose up -d
docker compose ps
docker compose logs --tail=100 postgres
docker compose logs --tail=200 arcreel
curl -f http://localhost:1241/health
```

`pgdata/` 保存 PostgreSQL 数据，`projects/` 保存项目元数据和生成媒体，二者必须分别纳入备份。应用启动时会执行数据库结构迁移，但迁移不能替代部署级备份。

### 4.3 模型和凭据配置

API Key 和供应商凭据应在客户部署环境中配置，不应写入源码、提交记录、日志或交付文档。

- 自由创作的视频生成至少需要配置可用的视频模型。
- 使用 Agent、固定工作流或脚本分析时，再配置对应文本模型。
- 使用图片生成、角色/场景/道具图像或图片编辑时，再配置对应图片模型。
- 供应商的模型能力、比例、分辨率、时长和参考素材限制以实际供应商配置及运行时校验为准。
- 第三方供应商的内容安全审核、限流、计费和服务可用性由供应商负责，交付方不承诺绕过其政策。

## 5. 验收清单

客户验收时应至少完成以下检查：

### 5.1 基础功能

- [ ] 服务能够启动并通过 `/health` 健康检查。
- [ ] 管理员能够登录和修改认证配置。
- [ ] 项目列表、项目创建、项目设置和关于页面可正常访问。
- [ ] MatrixSpooll 品牌和 ArcReel 来源声明显示正确。
- [ ] `LICENSE`、`NOTICE` 和源码交付物可以取得。

### 5.2 自由创作

- [ ] 可以创建自由创作项目并保留项目级画面比例和常用参数。
- [ ] 首页和项目详情页可以提交自由创作任务。
- [ ] Agent、生成图片、生成视频模式可以正常切换。
- [ ] 模型选择和模型检索可用，模型能力不支持的参数会给出明确提示。
- [ ] 参考素材、首尾帧和文本资源的上传、预览和引用行为符合验收设计。
- [ ] 任务成功、失败、取消和重试状态显示正确。
- [ ] 供应商错误能够转换为用户可理解的失败原因。

### 5.3 无限画布

- [ ] 图片、视频、音频和常用文本文件能够导入。
- [ ] 文件可以拖动、双击预览和按约定快捷键引用。
- [ ] 单选、框选、隐藏、删除、批量删除和撤销操作符合验收要求。
- [ ] 失败生成卡片能够进行删除或重试，不会误触发重复上传。

### 5.4 数据与运维

- [ ] 生成项目、媒体和数据库文件能够持久化。
- [ ] 完成一次数据库和项目目录备份。
- [ ] 使用备份完成一次恢复演练，恢复后的项目可以打开。
- [ ] 查看日志时不会暴露 API Key、Token、密码或用户隐私内容。

## 6. 客户需要提供的内容

客户应在部署或验收前提供：

- 服务器或本地运行环境；

- 域名、HTTPS、反向代理或 VPN（如需要远程访问）；

- 需要导入的历史数据及其格式说明；
- 业务验收人员和最终验收标准。

客户提供的 API Key 和业务数据由客户负责合法性、授权范围和保密管理。交付方不应在代码仓库或公共工单中保存这些内容。

## 7. 售后与变更

### 7.1 默认售后范围

以下内容应在合同中明确具体期限和响应时间：

- 部署启动问题；
- 交付版本中可复现的功能缺陷；
- 数据库迁移和备份恢复协助；
- 已配置供应商的接口适配问题；
- 使用文档和操作培训。

### 7.2 不属于默认承诺的内容

- 第三方模型供应商下线、涨价、限流或审核策略变化；
- 客户自行修改源码、配置或数据库造成的问题；
- 客户 API Key 失效、额度不足或权限变化；
- 客户素材的版权、肖像权、隐私权或内容合规问题；
- 未列入验收清单的新功能；
- 由客户基础设施、网络、域名、证书或存储故障导致的问题。

新增功能、供应商迁移、数据库改名、完全白标化或多租户改造应作为独立变更单评估，不直接视为本交付范围。
