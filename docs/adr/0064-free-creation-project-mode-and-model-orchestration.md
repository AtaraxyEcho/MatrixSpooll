# 自由创作作为项目内容模式并按请求编排模型

MatrixSpooll 增加项目级 `content_mode=free`，让自由创作留在项目边界内，但不进入源文件、脚本、分集、分镜或参考生视频工作流。自由项目的 `generation_mode` 为不适用值并落盘为 `null`，不能把 `free` 当作第三条视频生成路线；固定工作流项目创建时仍必须从 `storyboard` 与 `reference_video` 中选择一种生成方式。

实施拆分见 [自由创作实施方案](../superpowers/plans/2026-08-18-free-creation-implementation-plan.md)。

## 决定

- 自由项目复用项目级智能体会话、GenerationQueue、任务状态、SSE、成本记录和项目权限；自由结果在现有 `artifact_manifest` 中以 `free_creation_artifact` 资源类型登记，不伪装成分镜图、视频单元或剧集视频。
- 一次自由创作请求包含文本指令、参考素材、输出意图（图片/视频/编辑）和本次规格。项目比例只是默认值，自由请求可以按模型能力覆盖比例。
- 模型按请求形态编排：

  | 请求 | 文本模型 | 图片模型 | 视频模型 |
  | --- | --- | --- | --- |
  | 直接文生图 | 可选，用于理解、改写或工具路由 | 必需 | 不调用 |
  | 直接文生视频 | 聊天入口中通常需要；直连入口可跳过 | 不调用 | 必需 |
  | 图片编辑 | 可选 | 必需 | 不调用 |
  | 图片生视频 / 参考生视频 | 聊天入口中通常需要；直连入口可跳过 | 不调用，除非先生成或编辑参考图 | 必需 |
  | 多轮聊天创作 | 必需，负责上下文、意图和工具调用 | 按最终产物需要 | 按最终产物需要 |

- 不默认采用“文本模型 → 图片模型 → 视频模型”的固定三级流水线。用户明确要视频时直接调用视频模型；只有用户要求先定首帧、需要图片编辑，或视频模型明确要求图片输入时，才增加图片阶段。
- 文本模型的职责是理解上下文、识别输出意图、整理参考素材、进行可选的提示词增强以及调用媒体工具。应保留“原文直送”路径，避免每次生成都被文本模型改写。
- 聊天入口使用文本模型是产品交互的需要，不等于每个媒体任务都必须额外调用一次文本模型；非聊天的直接生成入口可以直接进入图片或视频 lane。

## 比例能力

首批产品预设为 `9:16`、`16:9`、`1:1`、`4:3`、`3:4`、`21:9`。火山引擎相关视频接口资料列出这六种比例（[接口参数说明](https://www.volcengine.com/docs/85128/1738950?lang=zh)），其 Seedance 2.0 产品页展示的预设集合又有所不同（[产品页](https://www.volcengine.com/product/dramart)），因此比例选择必须按实际 provider/model 能力动态筛选，不能由全局固定枚举决定。

MatrixSpooll 的底层比例计算支持任意正整数比例，但后端适配器可能只接受离散档位、按合法尺寸吸附，或要求参考图自适应。自由创作在入队前应完成能力校验，unsupported ratio 要显式失败，不能静默改成 `16:9`。

当前实现先提供六种产品预设和正整数 `width:height` 语法校验。按 provider/model 动态筛选及入队前能力拒绝必须等各 backend 有可核验的型号声明后再启用；在此之前不把六种产品预设误写成所有 Seedance 型号的共同白名单。

## 不采用

- **自由创作作为独立顶层工作区**：会割裂项目级会话、权限、成本和产物归档；项目模式已能提供隔离边界。
- **`generation_mode=free`**：把内容组织方式和视频输入契约混成一个轴，会迫使所有路线解析、能力分桶和费用逻辑增加错误分支。
- **所有请求强制经过图片模型**：增加延迟和成本，并会削弱直接文生视频的运动表达与用户控制。
- **只直连视频模型、不保留文本模型**：无法支持聊天上下文、意图分流、提示词增强和多轮编辑，也无法覆盖文生图和图片编辑。

## 后续影响

已实现自由项目 profile/skill、`creations/` 目录、队列任务和自由画布，固定项目的工作流状态机不会解释自由项目。自由创作 MCP 工具、正式 `artifact_manifest` 资源类型、归档往返、文本提示词增强及按型号比例能力仍按实施方案继续完成；这些能力完成前不得通过字段或界面暗示已经可用。
